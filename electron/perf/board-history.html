Board performance

Recorded by ./bin/board-timing --record, from electron/. Every row is the same method: a fresh build launched with a fresh profile, KiCad's Jetson AGX Thor demo opened on launch, then a pan, a zoom, a hover, a route into the largest footprint's pads, a short trace laid off a passive's pad, and a click on that footprint and a drag of it; one run per row. Board shown and open settled are ms since the main process started; settled means the renderer's main thread stayed under 10% busy for 2 s. Frame columns are the 95th-percentile frame interval during the gesture (16.7 is 60 fps); select is click to the frame after it, the route columns each cursor move to the frame that shows its route (pushed into the SoM connector's pads and abandoned), and trace → settled a short track laid off a passive's pad until the refill and checks it sets off are done. The design is named by its board file's git blob hash, and a row is recorded only from a design folder with no local edits. Headless runs under xvfb with software GL, so read CPU time and heap there and frame rate only from desktop runs (--visible, real GPU). Rows compare only within one machine, display mode and design, so each has its own table, newest first, each cell with its change from the row below. A * on a commit means the app's sources differed from it; the label says how.
